# 票务占座过期与出票一致性

使用者：演出票务渠道对账员。回放多渠道占座付款出票日志，找出售卖冲突与超时悬单。

核心规则：占座租约使用事件时间，付款时刻必须早于到期点，同版本冲突拒绝，释放后旧支付不能复活席位。

## 启动

```sh
docker compose up --build -d
docker compose exec -T app pytest -q
docker compose config --quiet
```

浏览器访问 http://localhost:18204 。首页已装载脏样例，可编辑CSV与参数后运行，也可上传文件。七个导航分别对应业务步骤。

## 模块

- M1 渠道接收：接收各渠道事件，入口 `/m/1`、`GET/POST /api/m1`。
- M2 座席映射：映射座席并裁决版本，入口 `/m/2`、`GET/POST /api/m2`。
- M3 租约回放：回放占座释放租约，入口 `/m/3`、`GET/POST /api/m3`。
- M4 支付归属：按有效租约归属支付，入口 `/m/4`、`GET/POST /api/m4`。
- M5 出票核验：检查支付及票号一致，入口 `/m/5`、`GET/POST /api/m5`。
- M6 渠道对账：核对渠道金额与悬单，入口 `/m/6`、`GET/POST /api/m6`。
- M7 补传复核：补传回放和版本复核，入口 `/m/7`、`GET/POST /api/m7`。
- M8 额度结算：按截止时刻结算渠道固定额度，入口 `/m/8`、`GET/POST /api/m8`、`POST /api/m8/receipt`。

## 截止结算（M8）

渠道开售前分到固定座席额度（`app/config.py::QUOTA`），截止时刻由参数 `settle_deadline` 给出。结算对16个额度座席逐席裁决：

- **成交已出票 / 成交待出票**：截止点前已收款（及出票）的成交，继续占用渠道旧额度，不回收、不重复卖。
- **回执待处理**：截止时占座租约仍有效但尚无成交回执，座席临时保留等待补传。
- **已回总池**：截止前未成交（租约已释放或到期）的空座，回收总池供临售。
- **拒绝回执**：原批次隔离的 pay/issue 逐笔列入回执台账；到达时已无有效占座的判 `LATE_REJECT`，座席已回池也不能被补传回执重新占用。

截止后到达的回执在 M8 回执台（`POST /api/m8/receipt`）逐条受理：落入有效占座区间才受理并占用旧额度，否则拒绝。同一事件号重放直接回放首次裁决；结算ID由批次、截止时刻与规则版本派生，重跑命中既有快照（`INSERT OR IGNORE`），同一结算绝不重复扣减。改变截止时刻会产生新的结算ID，互不覆盖。

## 演示与复核

1. 运行默认样例，核查隔离原因与业务合计。
2. 修改CSV单元格或参数并重跑，保留行号与输入摘要。
3. 在最后一步复核，旧版本提交返回409。
4. 证据CSV包含采信行和隔离行，重跑相同内容复用批次。

## 数据与目录

`app/modules/` 按业务切分；`sample_data/` 为UTF-8 BOM、GB18030及干净/脏样例；`tests/` 含规则与端到端测试。SQLite保存运行与复核，命名卷records保留重启后的记录。若需从头开始，可先停止服务并在确认不再需要记录后删除该项目records卷。

## 定义与边界

单场演出16个座席，不处理退票退款。占座租约释放或到期后，迟到付款不能恢复租约；出票必须已有有效付款且座席不可重复出票。截止结算逐席守恒：仍占旧额度 + 回执待处理 + 已回总池 = 固定额度16。

详细字段、计算定义与原因码见 `docs/DATA-DICTIONARY.md`，回归证据见 `docs/DEPTH.md`。
